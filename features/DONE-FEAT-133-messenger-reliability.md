## 1. Feature Brief (RU)

Батч 3 плана по улучшению чата — надёжность.

- **Мульти-таб (реальный баг).** Раньше `ws_manager` держал один сокет на пользователя и при
  новом подключении закрывал старый: открытие второй вкладки рвало сокет первой, вкладки
  «воевали» за соединение. Теперь на пользователя хранится множество сокетов, все вкладки
  работают параллельно и получают рассылки.
- **Индикатор связи.** При обрыве WS (дольше 2.5с) внизу появляется «Переподключение к
  серверу…», пропадает при восстановлении. Показывается только залогиненным.
- **Кулдаун вместо ошибки rate-limit.** Кнопка отправки кратко блокируется после отправки
  (личка 1с, общий чат 2с) — под лимиты бэкенда, чтобы юзер не ловил ошибку «Подождите…».

## 2-5. Technical

**Backend** (`notification-service`):
- `ws_manager.py` — `active_connections: dict[int, set[WebSocket]]`. `connect()` добавляет сокет
  (старые не закрывает). `disconnect(user_id, websocket=None)` — убирает конкретный сокет;
  подписки на каналы снимаются только когда у юзера не осталось сокетов. `send_to_user`,
  `broadcast_to_channel`, `broadcast_to_all` шлют во все сокеты. Публичный API совместим
  (сигнатуры send/broadcast не менялись).
- `main.py` — WS endpoint передаёт конкретный `websocket` в `disconnect()`.

**Frontend**:
- `components/common/ConnectionStatus.tsx` (new) — баннер переподключения с дебаунсом 2.5с.
- `components/App/Layout/Layout.tsx` — берёт `connected` из `useWebSocket`, рендерит баннер
  для залогиненных.
- `components/Messenger/MessageInput.tsx` — кулдаун 1с после отправки (не блокирует редактирование).
- `components/Chat/ChatInput.tsx` — кулдаун 2с после отправки.

**Tests** (`tests/test_websocket.py`): переписаны под мультиконнект — несколько сокетов на юзера,
закрытие одной вкладки оставляет остальные, send/broadcast во все сокеты. 17/17 зелёные.
