## 1. Feature Brief (filled by PM — in Russian)

### Описание
Подземелья существуют (dungeon-service, экран прохождения, визуальный редактор в админке), но ни разу
не были пройдены до конца и содержат много поломок (см. «Аудит» ниже). Пересобираем систему целиком:
игровые правила, исправление ошибок и новый визуал — подземелье как настольная игра на «столе судеб»,
в одной стилистике с 3D-ареной и книгами навыков.

### Бизнес-правила (согласованы с пользователем 2026-10-22)
1. **Откат общий для всех игроков** («кто успел, тот и съел»). Пока внутри подземелья есть группа,
   вход закрыт для всех остальных — одно подземелье = одна группа одновременно.
2. **Блокировка на время забега.** Пока персонаж в данже, он не может действовать снаружи
   (перемещение, посты на локациях, бои вне данжа, сбор ресурсов и т.п. — точный список ниже, в вопросах).
3. **Вайп (все погибли).** Группа теряет только полученное в этом рейде (общий инвентарь забега).
   Персонажей «выносит» на локацию, откуда они заходили, и они **без сознания 1 час реального времени**:
   персонажем нельзя ничего делать. Лор: «потеряли сознание, их вынесли из подземелья, очнулись позже».
4. **Группа = существующий отряд** (party-service). Своей системы приглашений в данже нет:
   в забег идёт лидер отряда со своими сопартийцами, стоящими на той же локации.
5. **Одиночный вход остаётся.**
6. Вход по-прежнему требует ролевого поста-намерения «Данж» (action gate).

### Визуал — «настольная игра на столе судеб» (выбран вариант 1)
- Подземелье — игровое поле, развёрнутое на столе богов (тот же стол, свечи, свет, что у арены и книг).
- Комнаты — плитки/карты: неисследованные лежат рубашкой вверх (туман войны), при входе переворачиваются.
- Группа — фигурки, которые переставляются по коридорам между плитками.
- Ловушки и засады — бросок костей (кости уже есть на арене).
- Бой начинается на этом же столе и переходит в 3D-арену; после боя — обратно на поле.
- Для устройств без WebGL и при «облегчённой графике» — 2D-карта (нынешняя, доработанная).
- Нагрузка на сервер не меняется: 3D рисуется в браузере, сервер шлёт те же события (пошагово, без real-time движения).

### UX / Пользовательский сценарий
1. Игрок (или лидер отряда) на локации видит вход в подземелье: свободно / внутри группа / откат N ч.
2. Пишет пост-намерение «Данж», нажимает «Войти» → один или отрядом (все сопартийцы на локации).
3. Стол: поле с перевёрнутыми плитками, фигурки на входе. Лидер выбирает коридор → фигурки идут,
   плитка переворачивается; засада/ловушка — бросок костей.
4. Комнаты: бой, босс, сокровищница, событие, отдых, торговец, телепорт (и «пустые» — развилка, тупик).
5. Финал: босс побеждён → сундук → дележ → выход, включается откат для всех.
   Побег → выход с риском потерять часть добычи. Вайп → выносят без сознания на 1 час, добыча забега теряется.

### Edge Cases
- Лидер вышел из игры/закрыл вкладку посреди забега.
- Участник ушёл из отряда во время забега.
- Брошенный забег (никто ничего не делает часами).
- Бой в данже завершился, когда никто не смотрит страницу.
- Двойные клики (сундук, торговец, дележ).
- Данж удалили/отредактировали, пока внутри группа.

### Блокировки (согласовано)
| Действие | В забеге | Без сознания (1 ч) |
|---|---|---|
| Перемещение по миру, телепорт | нельзя | нельзя |
| Посты на локациях | нельзя | нельзя |
| Бои вне данжа (свои, вызовы и нападения на него) | нельзя — «персонаж в подземелье» | нельзя — «персонаж без сознания» |
| Сбор ресурсов, крафт | нельзя | нельзя |
| Обмен с игроками на локации | нельзя | нельзя |
| Вход в данж | — | нельзя |
| Аукцион | можно | можно |
| Инвентарь и экипировка | можно | можно |
| Личные сообщения, чат (это игрок, а не персонаж) | можно | можно |
| Переключиться на другого персонажа аккаунта | можно | можно |

### Аудит текущего состояния (2026-10-22, кратко)
Критичное: телепорт-комната падает 500; персонажи застревают в «forming» при отказе входа; затаскивание
в данж без согласия; мобы данжа возрождаются на поверхности; после вайпа персонажи заблокированы 48 ч и
сессия не закрывается; нет таймаутов (брошенный забег вечно отключает регенерацию); результат боя
приходит только при открытии страницы (возможна двойная обработка наград); исходы событий сломаны
(бой/урон/лечение), урон ловушек не наносится; манаядро недостижимо, при успехе ломает данж навсегда;
частичный дележ нельзя завершить.
Среднее: гонки при двойных кликах; можно уйти на другую локацию посреди забега; откат не ставится при
побеге/вайпе; переподключение WebSocket закрывает само себя; рассинхрон фронта и бэкенда (имена
«Персонаж #id», «Предмет», «undefined», мёртвая кнопка «Перейти к бою»); несовпадение прав админки
(`dungeons:*` на фронте vs роль на бэкенде); мёртвые множители (мобы, опасность).
Данные: в единственном подземелье — телепорт в несуществующую комнату, боевая комната без мобов,
событие без вариантов. Документации сервиса нет (`docs/services/dungeon-service.md`).

### Этапы (предложение)
1. **Правила и надёжность (бэкенд).** Одна группа на подземелье; блокировка; вайп → «без сознания 1 ч»;
   отряды вместо своих приглашений; таймаут брошенных забегов; колбэк результата боя из battle-service;
   мобы данжа не выходят на поверхность; исправление всех критичных ошибок; права админки; документация.
2. **2D-экран по-новому.** Починка рассинхрона фронта/бэкенда на нынешней карте — данжи становятся
   проходимыми до 3D.
3. **3D-набросок стола.** Поле с несколькими плитками и фигурками — проверить направление.
4. **3D-данж.** Полноценное поле, переворот плиток, фигурки, кости, переход в арену и обратно; 2D как запасной.
5. **Админка и контент.** Проверка редактора, исправление данных подземелья, новые типы плиток при необходимости.

#### Must fix before commit
1. **Two groups can enter one dungeon concurrently** — `gameplay.py:618-623`. MySQL runs REPEATABLE READ; the re-check after `SELECT dungeons ... FOR UPDATE` is a plain (consistent) read that uses the snapshot taken by the transaction's first read (line 565), so a session committed by a concurrent entrant while we waited on the row lock is invisible → both inserts succeed. Fix: make the re-check a locking read (`.with_for_update()` on the occupying-sessions query) or commit before taking the dungeon lock so the snapshot starts after it; add a note/test.
2. **Ghost dungeon lock on a lock-call timeout** — `gameplay.py:646-662`. If `set_dungeon_lock` raises (e.g. httpx timeout) after character-service committed, `locked` stays False, the session is rolled back and the characters stay locked to a non-existent session forever (no sweeper/admin path can clear it). Fix: always call the (idempotent, session-scoped) `clear_dungeon_lock` in the except branch.
3. **Run stuck in `in_battle` when stamina spend fails after a battle was created** — `gameplay.py:1681-1686, 1714-1721` (`start_battle` writes Redis phase/active_battle_id before commit; `_spend_stamina` failure → DB rollback, Redis not rolled back, battle + mobs orphaned). Party can't move/act until the 24 h sweep. Fix: spend stamina before `start_battle` (refund not needed since checks passed), or on failure despawn mobs, force-finish/ignore the battle and reset the Redis phase.
4. **Entrants are not checked for an active surface battle / gathering** — `gameplay.py:519-530 (_check_entrant)`. A squadmate in a PvP/PvE battle (or gathering) is pulled into the run and locked; the surface fight continues and the dungeon battle then fails with «Персонаж уже в бою». Fix: skip such squadmates (reason «в бою»/«занят добычей»), refuse the leader.
5. **Frontend: no state refresh after WS (re)connect** — `DungeonSessionPage.tsx:260-264`, `useDungeonWebSocket.ts`. Events missed during a drop are never re-fetched (a finished run may never update). Fix: `refresh()` when `connected` flips to true.
